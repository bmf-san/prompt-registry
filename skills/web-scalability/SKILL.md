# Web スケーラビリティ

Web アプリケーション／分散システムのスケーラビリティと非機能特性に関わる主要トピック——CAP/PACELC、キャッシュ戦略、処理モデル、負荷試験、非機能要件——を横断的に評価・設計するための索引 skill。各トピックの詳細は `reference/` に置く。まず本ファイルで論点を掴み、必要な詳細を該当 reference で確認する。

- 分散データストア・キャッシュ層の整合性/可用性/レイテンシのトレードオフを検討するとき

## 判断の要点

- **分散システムでは分断（P）は前提**。実質の選択は分断時に一貫性を取るか可用性を取るか（CP か AP）。さらに通常時のレイテンシ vs 一貫性まで見るなら PACELC で評価する。詳細は reference/cap-pacelc.md。
- **キャッシュ戦略は読み書きの頻度と整合性要件で選ぶ**。読み中心で整合性重視ならライトスルー、書き込み性能最優先で消失リスク許容ならライトバック、細かい制御が要るならキャッシュアサイド。「書いた直後に読む」データはライトアラウンドと相性が悪い。
- **処理モデルはワークロードで選ぶ**。IO バウンドはイベントループ、CPU バウンドはスレッド/プロセス。GIL のある言語（Ruby MRI・Python CPython）で CPU 並列を期待した設計にしない。
- **負荷試験はまず目的を定める**。目的（ロード/ストレス/ソーク/ベースライン）に手法を合わせ、性能目標は具体的な数値で置き、シナリオは実際の使われ方を反映する。事前に監視ダッシュボードと関係者共有を用意する。
- **非機能要件は ISO/IEC 25010 の8特性で網羅確認し、優先順位とトレードオフを明示する**。すべてを最大化しようとせず、要件に対して過剰でも不足でもない設計にする。コスト効率・コンプライアンスは規格外だが実務上追加で見る。
