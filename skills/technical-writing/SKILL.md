# テクニカルライティングと編集

読者の理解と納得を導くために、文章を戦略的に書き・評価し・改善する。単なる添削や誤字脱字の指摘ではなく、構成・論理展開・表現の質を高めることを狙う。執筆と編集は同じ「6つの文書特性」を評価軸として共有する。

## いつ使うか

- 記事・設計文書・技術ドキュメントを書き始めるとき（準備・アウトライン・執筆）
- 既存の文章をレビュー・編集・校正するとき
- 「何を書けばいいか整理したい」「読みにくいと言われた」「観点を揃えてレビューしたい」とき

## 6つの文書特性

執筆・評価の共通の軸。文章はこの6観点でチェックする。

| 特性 | 見るポイント |
|-----|------------|
| **正確性** | 記述内容は事実に基づき、読者の関心事に対して正確か |
| **十分性** | 判断理由や背景が示されているか。代替案があれば比較・選択理由が説明されているか |
| **簡潔性** | 重要なポイントに焦点が絞られているか。詳細度は読者の知識レベルに適切か |
| **明瞭性** | 専門用語は読者のレベルに合っているか。図表などの視覚的工夫があるか |
| **通用性** | 最新の状況を反映しているか |
| **精密性** | 必要な詳細が記述されつつ、可読性が保たれているか |

## 執筆のワークフロー

### 1. 執筆準備（本文を書く前に必ず行う）

やること:

1. 目的と対象を明確化する。次の3点を確認する（不明なら書き手に質問する）。
   - **対象読者**: 誰に向けた文章か（技術的能力・経験・関心事）
   - **目的**: 文書が何を伝えることを目的とするか
   - **核心的なメッセージ**: 最も伝えたいことは何か
2. アウトラインを作成し、承認を得てから本文に進む。
   - 見出しを追うだけで全体の流れと主要ポイントが理解できること
   - 大・中・小見出しを使い分け、論理構造を明確にすること

### 2. 段階的な執筆

守ること:

- **全体から詳細へ**: 最初から詳細を含めすぎず、まず全体像を作る
- **簡潔性を優先**: まず簡潔に書き、その後に詳細や説明を足す
- **焦点を絞る**: 一つの見出しにつき一つの主題に集中する
- **認知負荷を下げる**: 読者が一度に多くを処理しないよう、段階的に理解を深められる構成にする

### 一次情報の引き出し

一般論に終始させないため、執筆中に書き手へ問いかけて独自の視点を盛り込む。

- 体験の具体化: 「このテーマについて、自身の体験はあるか？」
- 具体例の発掘: 「具体的な例はあるか？」
- 意見の明確化: 「このポイントについての意見・考えは？」

## レビュー・編集のワークフロー

### 準備

1. **通読**: 文章全体を読み、全体像を把握する
2. **構造の確認**: 見出し構成・章立て・論理展開を確認する
3. **主要な問題点の特定**: 6つの文書特性の観点から主な課題を洗い出す

対象読者やレビューの焦点が不明な場合は確認する。文章から読み取れる場合は推測で進めてよい。

### 評価の観点

6つの文書特性に加え、次を体系的に見る。

- **構成と論理**: 見出しだけで要旨が掴めるか／主張と根拠の関係は明確で飛躍がないか／情報の順序は理解しやすいか／トーン・スタイル・視点が統一されているか
- **読者視点**: 一度に情報を詰め込みすぎていないか（認知負荷）／読者の前提知識に合っているか／抽象論だけでなく具体例があるか／関心を引く工夫があるか

細かな観点は [reference/review.md](reference/review.md) のチェックリストを使う。

### 改善提案の出し方

守ること:

- 問題点の指摘だけで終わらせず、必ず改善案と改善理由をセットで示す
- 個人的な好みではなく、読者視点と文書の目的を判断基準にする
- 改善案が複数ある場合は、それぞれのメリット・デメリットを添える

各指摘は優先度を付けて次の形式で提示する。

```
【優先度】Critical / Important / Nice to have

【該当箇所】
（元の文章を引用）

【問題点】
何が問題か（6つの特性のどれに関わるか）

【改善案】
具体的な修正内容

【改善理由】
なぜこの修正で改善されるのか
```

優先度の基準:

- **Critical（必須）**: 内容の正確性や論理性に関わる重大な問題
- **Important（推奨）**: 読みやすさや説得力を大きく向上させる改善
- **Nice to have（任意）**: より良くするための細かい改善

軽量に添削だけ返す場合は【問題点】【改善案】【改善理由】の3点でもよい。

### 修正の進め方

- **部分的に修正**: セクションごとに修正して確認を取る（承認なしに全体を一括修正しない）
- **修正内容の説明**: 何をどう変えたかを明確に伝え、意図を説明せず書き換えない
- **整合性チェック**: 修正箇所が他の部分と矛盾していないか確認する
- 著者の意図やスタイルを尊重し、無視して書き直さない
