# システム設計のレビューチェックリスト

システム設計をレビューする際に確認すべき項目。

## 評価観点

適切性（要件を満たすか）・一貫性（パターンが一貫適用されているか）・実現可能性（スキルや制約の中で可能か）・保守性（長期的に保守できるか）・リスク（技術的リスクはないか）の5観点で見る。

## 要件との適合性

- [ ] すべての機能要件を満たしているか
- [ ] 非機能要件（パフォーマンス、可用性など）を満たしているか
- [ ] 制約条件（予算、時間、技術）の中で実現可能か

## アーキテクチャの品質

- [ ] 責務が明確に分離されているか
- [ ] コンポーネント間の結合度は低いか
- [ ] コンポーネント内の凝集度は高いか
- [ ] 単一障害点はないか
- [ ] スケーラビリティは確保されているか

## データ設計

- [ ] データモデルは正規化されているか（必要に応じて）
- [ ] インデックス設計は適切か
- [ ] データの整合性は保証されているか
- [ ] バックアップ・リカバリ戦略はあるか

## セキュリティ

- [ ] 認証・認可の仕組みは適切か
- [ ] データの暗号化は適切か
- [ ] OWASP Top 10 への対策はあるか
- [ ] 監査ログは設計されているか

## 運用・保守

- [ ] ログ設計は適切か
- [ ] 監視・アラートの仕組みはあるか
- [ ] デプロイ戦略は明確か
- [ ] ロールバック手順は定義されているか
- [ ] ドキュメントは十分か

## 将来性

- [ ] 新機能の追加は容易か
- [ ] 技術的負債の蓄積を防げるか
- [ ] 段階的な移行は可能か（既存システムがある場合）

## アンチパターン

設計に以下が紛れていないか確認する。

- **構造的**: God Object（神クラス）、Spaghetti Code、Circular Dependency（循環依存）
- **パフォーマンス**: N+1 Query Problem、不適切なキャッシング、同期処理の過度な使用
- **セキュリティ**: Hard-coded Credentials、Missing Authorization（認可不足）、Unvalidated Input（入力値検証の欠如）

## 改善提案の提示方法

```
【現在の設計】問題のある設計を説明
【問題点】アンチパターン・リスク・非効率性
【改善案】改善後の設計
【改善理由】なぜ改善されるか・利点・トレードオフ
【影響範囲】既存システム・開発コストへの影響
```
