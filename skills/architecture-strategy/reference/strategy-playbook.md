# アーキテクチャ戦略プレイブック

ビジネス目標と技術を結びつけ、中長期的な視点でシステムの方向性（Why & What）を定めるための手順とテンプレート。方向性の承認を得てから詳細を作成する。成果物はアーキテクチャ戦略書（後掲のテンプレート）。

## 1. 戦略策定の準備

### 1.1 ビジネス戦略の理解

- **ビジネス目標**: 今後1〜3年で達成したい目標、ターゲット市場・成長戦略、競合優位性
- **事業の性質**: スタートアップ（1〜2年視点）か成熟事業（3〜5年視点）か、変化速度、規制産業か新規市場か
- **組織の状況**: 開発チームの規模と成長計画、技術スキルセット、組織文化（イノベーション重視 or 安定性重視）

### 1.2 現状の診断

- **技術的現状**: 現在の技術スタック、システム構成（モノリス／マイクロサービス等）、既知の技術的負債
- **課題の特定**: 開発速度のボトルネック、品質・安定性、スケーラビリティ、セキュリティリスク
- **組織的現状**: 技術的意思決定プロセスの有無、チーム間の技術スタックのばらつき、知識共有の状況

## 2. 戦略の策定

### 2.1 基本方針（原則）の策定

技術的意思決定の基準となる原則を定義する。**3〜5個に絞り**、各原則に Why（理由）と What（目標）を明記し、トレードオフ（何を優先し何を犠牲にするか）を明示する。

```
【原則1】スピード優先
Why: スタートアップフェーズで市場投入速度が競争優位の鍵
What: 機能開発のスピードを最優先し、過度な最適化は避ける

【原則2】技術スタックの統一
Why: チームが小規模で、保守コストを抑える必要がある
What: フロント・バックとも単一の主要技術に統一する
```

### 2.2 目指す姿（To-Be）の定義

中長期に目指すアーキテクチャの姿を Why & What で定義する。手段を目的化しない。

- ✗ 悪い例: 「マイクロサービスにする」（手段が目的化）
- ◯ 良い例: 「チーム自律性を高め、機能ごとに独立してリリースできるようにする（そのためにマイクロサービス化を検討）」

```
【目指す姿】

## システム構成
【Why】チーム規模が拡大し（現在10名→3年後30名）、単一リポジトリでの開発が限界に達する。
【What】機能ドメインごとにサービスを分割し、チームが自律的に開発・運用できる体制を構築する。
【制約・前提】既存モノリスは段階的に移行（ビッグバンリライトは避ける）

## 技術の方向性
【Why】オンプレミス環境ではトラフィック変動への対応コストが高い。グローバル展開を見据える。
【What】クラウドネイティブなアーキテクチャでスケーラビリティとコスト最適化を実現する。IaC で再現性を確保する。
```

### 2.3 ギャップ分析と優先順位付け

現状（As-Is）と目指す姿（To-Be）のギャップを分析し、優先順位をつける。

```
【ギャップ1】モノリス構成によるデプロイの相互依存
【現状の問題】一部の変更で全体をデプロイ、チーム間調整が頻発しリリース速度が低下
【To-Be とのギャップ】機能ドメインごとのサービス分割ができていない
【優先度】High（ビジネス目標「機能リリース速度2倍」に直結）
【影響度】ビジネス: 高／技術: 高／実現難易度: 中（段階的移行で対応可能）
```

優先順位付けの基準: (1) ビジネス目標への貢献度 (2) 技術的リスクの大きさ (3) 実現の難易度とコスト (4) 他施策への影響。

## 3. アーキテクチャ戦略書テンプレート

戦略書は必ず「課題分析→方針→施策」の3要素で構成する。

```markdown
# アーキテクチャ戦略書

## 1. エグゼクティブサマリー
- 戦略の目的（Why）／主要な課題（3点以内）／方針の概要／期待される効果

## 2. ビジネスコンテキスト
- ビジネス目標 / 事業の性質 / 組織の状況

## 3. 課題分析（Diagnosis）
根本原因を特定する。表面症状で終わらせない。
### 3.1 現状（As-Is）: システム構成・技術スタック・開発プロセス
### 3.2 主要な課題（各課題ごとに）
- 現象 / 根本原因 / ビジネスへの影響 / 優先度（High/Medium/Low）/ 定量的データ
### 3.3 課題の優先順位

## 4. 方針（Guiding Policy）
Why と What を明確にする。How は含めない。
### 4.1 基本方針（各方針ごとに Why / What / トレードオフ）
### 4.2 やること・やらないこと（リソース配分の線引き）

## 5. 施策（Coherent Actions）
方針を実現する具体的アクションの大枠を優先度順に示す。
### 5.1 施策の方向性（各施策ごとに 内容 / 解決する課題 / 期待効果 / 実施時期）
### 5.2 実行計画（フェーズ1・2・3）

## 6. 成功指標（KPI）
ビジネス指標 / 技術指標 / 組織指標（現状と目標を数値で）

## 7. リスクと対応方針
各リスクごとに 内容 / 影響度 / 発生確率 / 対応方針

## 8. ガバナンス
意思決定プロセス（判断基準・エスカレーションルート）/ 定期的な見直し（四半期ごと推奨）
```
